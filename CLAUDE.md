# Журнал тренировок: правила проекта

Устройство как в FAS (`/Users/philip_moriss/frilance/FAS/CLAUDE.md`), упрощённое: одна роль, данные принадлежат аккаунту.

```
apps/
  backend/   NestJS: модули, DI через интерфейсы
  web/       React + Vite, архитектура FSD
```
Запуск и проверки — в README.md.

## Общие правила

- **Каждое приложение — самостоятельный проект** со своими `package.json` и `node_modules`. Корневого `package.json` нет. Приложения не импортируют код друг друга.
- **Источник правды по API — бэкенд** (DTO + Swagger на `/docs`). Типы, которые нужны клиенту (ключи мышц, единицы, формат записи), web держит у себя в `entities/*/model`. Ключи не переименовываем без обновления клиента.
- Никаких циклических зависимостей. Проверка: `npm run lint:deps` в обоих проектах.
- **Данные пользователя** — только его: каждый запрос фильтруется по `userId` из токена, а не из параметров. Доступ закрыт по умолчанию (глобальный guard), открытые эндпоинты помечены `@Public()`.
- **Секреты:** код входа — хеш (scrypt + соль + `CODE_PEPPER`) и HMAC для поиска при входе без логина (`codeLookup`, уникален, есть только у 8-значных кодов); в открытом виде код отдаётся один раз. `CODE_PEPPER` не менять — все коды перестанут подходить. Старые 6-значные коды работают как пароль к логину; смена кода (`POST /api/auth/code`) выдаёт 8 цифр и растит `sessionsVersion`. Refresh-токены — хешем в `sessions`, одноразовые.
- **Совместимость со старой версией:** id упражнений из шаблона («bench», «row»…) совпадают с ключами прежнего приложения — на них ссылаются старые записи и черновики. Не менять.

## Backend (NestJS)

Модули: `accounts` (логин, код, лимит попыток), `auth` (регистрация, вход, сессии, guard), `program` (упражнения, цикл, расписание, правила, шаблоны), `journal` (записи, импорт, черновики), `health`.

- Структура модуля: `controllers/ services/ dto/ entities/ tests/ <module>.module.ts index.ts`. e2e — в `apps/backend/test/`.
- Связи между модулями — через контракты в `src/shared/contracts/` (DI-токен + интерфейс). Импорт чужого модуля — только в `*.module.ts`.
- Ссылки на чужие таблицы — uuid-колонка + `@ForeignKey('<таблица>')`, без ORM-связей.
- База меняется только миграциями (`synchronize` выключен), даты — `timestamptz`, дни — `date` (YYYY-MM-DD считает клиент в своём поясе).

## Web (FSD)

- Слои: `app → pages → widgets → features → entities → shared`. Импорт только вниз, слайсы одного слоя не импортируют друг друга, чужой слайс — через `index.ts`.
- Запросы: `queryOptions` в `entities/*/api`, мутации (с оптимистичным обновлением кэша) в `features`.
- Дизайн «Flying Papers»: токены в `app/styles/index.css`, палитра для Excel — `features/export-xlsx/model/palette.ts`. Плоские кремовые карточки 6px на фиолетовой сцене, pill-кнопки, без теней; жёлтый — акцент и контур.
