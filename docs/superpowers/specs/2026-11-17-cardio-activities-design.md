# Доп. тренировки: бассейн и велосипед

Дата: 2026-11-17. Статус: согласовано в чате, дальше — план реализации.

## Зачем

Основа приложения — программа в зале. Клиенту нужно иногда записать кардио рядом с ней: сколько проплыл в бассейне и сколько проехал на велосипеде. Это дополнение к залу: программа, прогрессия, награды и ИИ его не учитывают.

## Решения из обсуждения

| Вопрос | Решение |
|---|---|
| Виды | `swim` (бассейн) и `bike` (велосипед). Другие виды добавятся новым значением `kind` |
| Бассейн | Длина дорожки (25 / 50 м или своя) × сколько раз проплыл дорожку = дистанция |
| Велосипед | Дистанция в км |
| Время | Обязательно для обоих. Из него клиент считает среднюю скорость (велик, км/ч) и темп (бассейн, мин:сек на 100 м) |
| Где в интерфейсе | «Сегодня»: кнопка «+ Доп. тренировка» и карточки за день. «Дневник»: кардио показано в днях рядом с записями зала |
| Тренер | Видит кардио клиента только на чтение |
| Хранение | Отдельная таблица `activities`. В `entries` кардио не пишем: на `entries` держатся прогрессия, награды, ИИ и Excel |

## Данные (миграция `Activities`, модуль `journal`)

Таблица `activities`, сущность `entities/activity.entity.ts` (`BaseEntity`: `id`, `createdAt`, `updatedAt`):

| Колонка | Тип | Заметки |
|---|---|---|
| `userId` | uuid, `@ForeignKey('accounts')`, `onDelete: CASCADE` | |
| `date` | `date` | YYYY-MM-DD, считает клиент в своём поясе |
| `kind` | `varchar(10)` | `swim` \| `bike` |
| `poolLength` | `smallint null` | метры, только `swim` |
| `laps` | `int null` | сколько раз проплыл дорожку, только `swim` |
| `distanceM` | `int` | метры. Для `swim` всегда `poolLength × laps`, считает сервер |
| `durationSec` | `int` | > 0 |
| `notes` | `text default ''` | |

Индекс `(userId, date)`. Скорость и темп не храним.

## API (`journal.controller.ts`, префикс `/api/journal`)

| Маршрут | Доступ | Что делает |
|---|---|---|
| `GET activities` | client, `@CoachAccess('read')` | Всё кардио пользователя, по `date` убыв., затем `createdAt` убыв. (как `GET entries`; «сегодня» фильтрует клиент) |
| `POST activities` | только client | Создать |
| `PATCH activities/:id` | только client | Изменить свою запись, чужая → 404 |
| `DELETE activities/:id` | только client | Удалить свою запись, 204 |

Полный сброс дневника (`DELETE /journal`) удаляет и кардио.

**DTO `CreateActivityDto`:** `date` (ISO_DATE), `kind` (`IsIn(['swim','bike'])`), `durationSec` (int, 1…86 400), `notes?` (до 2000). Для `swim`: `poolLength` (int, 10…100) и `laps` (int, 1…1000) обязательны, `distanceM` не принимается. Для `bike`: `distanceM` (int, 100…500 000) обязателен, `poolLength`/`laps` не принимаются. Диапазоны проверяет DTO, сочетание полей с видом — чистая функция `activityDistance` в сервисе (`BadRequestException`): лишние поля для вида → 400.

**`UpdateActivityDto`:** все поля `CreateActivityDto`, кроме `kind`, необязательны; `kind` в правке отбрасывается (`whitelist`). Сервис сливает правку с текущей записью, проверяет итог по правилам вида и пересчитывает `distanceM` для `swim`.

**Сервис** `services/activities.service.ts`: `list(userId)`, `create(userId, dto)`, `update(userId, id, dto)`, `remove(userId, id)`, `removeAll(userId)`. Все запросы фильтруются по `userId` из токена.

## Web (FSD)

**`entities/activity`**
- `model/types.ts`: `ActivityKind`, `Activity`, `ActivityInput`.
- `model/metrics.ts`: `speedKmh(distanceM, durationSec)`, `pacePer100m(distanceM, durationSec)` (возвращает секунды), форматтеры `formatDuration` (`ч:мм:сс` / `мм:сс`), `formatDistance` (м до 1000, дальше км с одним знаком), `formatPace` (`м:сс/100 м`).
- `api/queries.ts`: `activitiesKey = ['journal', 'activities']`, `activitiesQuery()`, `useActivities()`.
- `ui/activity-line.tsx`: иконка (lucide `Waves` / `Bike`), название и строка: «1 000 м · 40×25 м · 22:30 · 2:15/100 м», «32,4 км · 1:12:00 · 27,0 км/ч». Бассейн — всегда в метрах, велик — в км.
- `CoachClientScope` (`app/router/guards.tsx`) при смене клиента выбрасывает и кэш `activitiesKey`.

**`features/log-activity`**
- Шторка с формой: переключатель «Бассейн / Велик» (pill-кнопки).
  - Бассейн: дорожка (пилюли 25 / 50, можно ввести своё значение), «Сколько раз», время (минуты и секунды).
  - Велик: км (с десятичными), время (часы, минуты).
  - Ниже — пересчёт «Дистанция … · Темп …» / «Скорость … км/ч» по мере ввода.
  - Заметка.
- Мутации создания, правки и удаления с оптимистичным обновлением кэша `activities`. Удаление — сразу, иконкой корзины, как у записей. Без сети кардио не копится (очередь `pending` — только у записей зала).
- Для правки шторка открывается с заполненными полями; вид поменять нельзя.

**«Сегодня» (`pages/today`)**: под тренировкой зала — блок «Доп. тренировки»: карточки за сегодня (тап — правка) и кнопка «+ Доп. тренировка». Показывается и в день без тренировки по расписанию.

**«Дневник» (`pages/journal`, `widgets/journal-list`)**: в каждом дне после записей зала — плашки кардио. День, в котором есть только кардио, тоже показывается. В кабинете тренера плашки те же, без правки и удаления (тренеру мутации кардио закрыты и на сервере). Запрос идёт на `/journal/activities`, поэтому `CoachClientScope` сам подставляет `X-Client-Id`.

Дизайн — «Flying Papers»: кремовые карточки 6px, pill-кнопки, без теней, жёлтый — акцент.

## Тесты

- Unit (`journal/tests/activities.spec.ts`, функция `activityDistance`): `distanceM` для `swim` = дорожка × раз; отказ на `bike` с `laps`, на `bike` без дистанции, на `swim` без `poolLength`, на `swim` с `distanceM`.
- Пересчёт после `PATCH` только `laps` и то, что `kind` в правке не меняется, — в e2e.
- Web: тест-раннера в `apps/web` нет, новый не заводим. Проверка — `npm run typecheck`, `npm run lint`, `npm run lint:deps` и прогон в браузере (запись бассейна и велика, правка, удаление, дневник тренера).
- e2e (`apps/backend/test/activities.e2e-spec.ts`): клиент создаёт / читает / правит / удаляет своё кардио; чужое → 404; тренер читает кардио привязанного клиента через `X-Client-Id`, на `POST`/`PATCH`/`DELETE` получает 403; сброс дневника удаляет кардио.
- `npm run lint:deps` в `apps/web` и `apps/backend`.
